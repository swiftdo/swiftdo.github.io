> 「打字。回车。一份能交付的设计。」

前两篇设计类工具都在争一件事：什么算好看。这一篇换了个问题——**做出来的东西能不能交付**。

| 项目 | 内容 |
|---|---|
| 类型 | Agent Skill（HTML 原生，跨 agent） |
| 仓库 | [alchaincyf/huashu-design](https://github.com/alchaincyf/huashu-design) |
| 技术栈 | HTML/CSS/JS + Node 导出链（ffmpeg、Playwright、html2pptx） |
| 许可 | MIT（2026-05-14 起；此前是「个人免费、商用需授权」） |
| 热度 | 28.3k star / 3.1k fork / 0 open issue（2026-10-31 快照） |
| 状态 | v3.1.0（2026-10-30），四个月前才开源 |

## 它和前两篇不是同一个东西

同样是「让 agent 做设计」，三者的优化目标完全不同：

| | taste-skill | impeccable | huashu-design |
|---|---|---|---|
| 优化什么 | 从零长出一个想法 | 把已有界面推到合格 | **产出能直接交付的文件** |
| 判定方式 | CDP 三档宽度量 | 62 条确定性规则 | 设计体检只量事实，好不好看你判 |
| 典型产物 | 一个页面 | 改好的一版界面 | HTML 原型 / PPTX / MP4 / PDF / 3:4 图 |
| 耗时 | 30–45 分钟 | 按命令，几分钟一轮 | 3–30 分钟一件交付物 |

交付物那一列是关键。它真正解决的不是「好不好看」，是「做完了能不能发出去」：

| 能力 | 交付物 | 典型耗时 |
|---|---|---|
| 交互原型（App / Web） | 单文件 HTML，真 iPhone bezel，可点击，Playwright 验证 | 10–15 min |
| 演讲幻灯片 | HTML deck + **可编辑 PPTX**（文本框保留） | 15–25 min |
| 时间轴动画 | MP4（25/60fps）+ GIF + BGM | 8–12 min |
| 信息图 | 印刷级排版，可导 PDF/PNG/SVG | 10 min |
| 小红书图文 | 3:4 一组图（≤18 张），8 种范式 | 10–15 min |
| 设计方向顾问 | 六个候选 → 三版真稿 | 10 min |
| 5 维度评审 | 雷达图 + Keep/Fix/Quick Wins | 3 min |

那个「可编辑 PPTX」值得单独说：`html2pptx.js` 读 DOM 的 computedStyle 逐元素翻译成 PowerPoint 对象，导出的是**真文本框**，不是图片贴片。这一条把「AI 做的设计」从「截图给你看」变成了「同事能接着改」。

## 核心一：先给六个候选，挑三个做真稿

需求模糊时它不猜，走一套叫「设计方向顾问」的流程——三套逻辑各出两个候选：

1. **最佳设计师**：两位气质不同的设计师，用他们的思维方式从头做一遍
2. **现实参照**：两件**同媒介**的获奖作品——做 App 找 App，做 deck 找出版物；`ref_board.py` 先把参考截图成参考板，agent **亲眼看**过再动手，然后拆它的网格、字号比、色彩比例
3. **秒数轮盘**：`date +%S` 取当前秒数，在对应分区里随机抽一号，先看样张再开工——刻意用随机性打破惯性

六个先画成一页缩略图，挑**最强、最不一样、又不撞你最近项目**的三版做成真实视觉，另外三张作为备选一起给你。

规矩只有一条，写在文档里：**绝不让你在没看到视觉时盲选风格**。

背后是 **92 种 HTML 原生风格库**，每种配一张样张和源码（纯 CSS，不需要生图）：网页 20 + PPT 20 + 信息图 20 + App 12 + 中文与东亚 12 + 小红书 8。3.1 新增的就是最后那 8 种小红书范式。

![中文与东亚风格 12 种：吕敬人书籍设计、宋刻本版式、民国书衣、上海摩登、中文实验字体、香港街招、传统色节气、杉浦康平、田中一光、服部一成、佐藤可士和、日式杂志密排](/imgs/ai-toolbox/huashu-design/sheet-east.jpg)

![App 风格 12 种：硬件面板、液态玻璃、玩味 3D、友好金融、专业相机、户外地形、内容瀑布流、命令面板、健康数据、原生精修、柔和鼓励、编辑式阅读](/imgs/ai-toolbox/huashu-design/sheet-app.jpg)

这两张图本身就能说明问题：同一份需求，落在「民国书衣」和「液态玻璃」上会是两个完全不同的产品。所谓「风格库」，本质是把「往哪个方向走」变成可以指着选的选项，而不是一句「做得高级一点」。

## 核心二：加选项，不加禁令

这是全篇最值钱的一段，因为它的结论是**输出来的**。

作者拿固定题目做了三轮改前改后盲选（内部测试，没有第三方复现）：

| 轮次 | 做法 | 结果 |
|---|---|---|
| 第一轮 | 强制每版套一个大隐喻，让页面变成道具 | 4 题只赢 1 题 |
| 第二轮 | 为躲开 AI 默认外观，加了一堆禁令 | 三版一起变得「太规整、太无聊」，2 题全输 |
| 第三轮 | 改成**加选项、不加禁令**：多给候选、给看得见的样张、看真参考 | 同两道题都赢 |

第二轮的失败特别值得记住：**禁令会让所有版本一起收敛**。你禁掉紫渐变、禁掉卡片、禁掉小标签，最后三版确实都不像 AI 了——但也不像任何东西了。

所以它明确写了：暖纸衬线、深底单点缀这类「外观家族」**不在禁令里**。理由很实在——盲选里被用户认可的几版，恰好就有这两类。真正要避免的不是某个家族，是**三版挤在同一个家族、每个项目都长一个样**。

那这件事交给谁管？见下一节。

## 核心三：它记得你（状态在文件里，不在上下文里）

三个只写在本机 `~/.huashu-design/` 的东西：

- **经验**：`scripts/learn.py` 开工前带出你说过的品味原话（「太素了」「A 的结构加 C 的颜色」）和过去的教训，收工时把值得记的记下来；记录前会告诉你，不想记可以拒绝。
- **外观账本**：每次交付记一笔「长什么样」——底色、色板、字体、版式骨架，连同项目名和路径。下个项目主动避开。**单个项目看都不错、放在一起却长得像**，这种单调靠它管。
- **设计体检**：`scripts/design_lint.py` 只量能核对的事实——图裂了、字小到读不了、对比度不够、控制台报错，红灯；全大写小标签、「A · B · C」这种顺手模板装饰，黄灯；三版是不是换皮、跟最近项目撞没撞，用 `compare` 和 `ledger check` 查。

最后一条的措辞很关键：**好不好看归你判断，它不打分**。

这和前一篇 impeccable 的 62 条规则是两条路：一个把审美判定做成可 FAIL 的规则，一个把审美判定留给人、只把事实和「重复度」自动化。它对「单调」的解法不是禁某类风格，而是记住你做过什么、下次别撞。

## 有意思的地方：它和 impeccable 打起来了

两件事放在一起看：

- impeccable 的 `cream-palette` 规则说：暖奶油/米色背景已经是条件反射式的「得体」AI 表面，判 slop。
- huashu-design 说：暖纸衬线不在禁令里，因为盲选里用户认可的几版恰好是这类。

同一个现象，一个禁、一个不禁，各有各的依据。谁对？

我的判断是两边都对了一半：**impeccable 在防下限**（大量页面确实是反射性选了奶油色），**huashu-design 在防平庸**（禁令会让三版一起变得规整无聊）。这两件事不是同一个目标，用同一套规则去同时满足，会长出很别扭的东西。

也顺便说明了一件事：这类「审美规则」不是客观真理，是各自语料的投影。impeccable 的规则来自 247 个获奖站的统计，huashu-design 的结论来自它自己那几十道题的盲选——**样本不同，结论就会相反，而且都拿得出数据**。

## 品牌资产协议：5 步硬流程

Skill 里最硬的一段，涉及具体品牌时强制执行：

| 步骤 | 动作 |
|---|---|
| 1 · 问 | 用户有 brand guidelines 吗 |
| 2 · 搜官方品牌页 | `<brand>.com/brand` · `brand.<brand>.com` · `<brand>.com/press` |
| 3 · 下载资产 | SVG → 官网 HTML 全文 → 产品截图取色，三条兜底，上一条失败立刻走下一条 |
| 4 · grep 提色值 | 从资产里抓所有 `#xxxxxx`，按频率排序，过滤黑白灰 |
| 5 · 固化 spec | 写 `brand-spec.md` + CSS 变量，所有 HTML 引用 `var(--brand-*)` |

第 4 步那句是全篇最实用的一条纪律：**绝不从记忆猜品牌色**。作者做过 A/B（v1 vs v2，各跑 6 个 agent），称 v2 的稳定性方差比 v1 低 5 倍——这是作者自测，没有第三方复现，但方向是对的：把「查」变成流程，比指望模型记性可靠。

## 安全与数据流

这点它写得比多数项目清楚，也值得一记：

- 核心链路（设计 → 渲染 → MP4/PDF/PPTX 导出）**100% 本地，零网络零 key**。
- 云能力（豆包 TTS 配音、AI 看片评审）全部隔离在 `scripts/cloud/`，完全可选，用你自己的 key，首次调用要 `--yes` 显式确认。
- **无 telemetry**，没有任何数据发往作者服务器。
- 品味经验、外观账本只写在 `~/.huashu-design/`，删掉文件夹就全部忘记。

## 上手

```bash
npx skills add alchaincyf/huashu-design
```

**装完必须自检。** 这不是一个 SKILL.md 就能跑的技能：`references/`、`assets/`、`scripts/`、`demos/` 四个子目录里有 **99 处被引用**的配方、脚本、素材。而 `skills` CLI 在 **≤1.5.15 有个只同步单文件的 bug**，装完可能只有一个 SKILL.md。

检查安装目录（如 `~/.claude/skills/huashu-design/`），如果子目录缺失：

```bash
npm i -g skills@latest    # 1.5.19 已修
# 或者干脆用 git 兜底
git clone https://github.com/alchaincyf/huashu-design.git ~/.claude/skills/huashu-design
```

然后在任意支持 skills 的 agent 里直接说话：

```text
「做一份 AI 心理学的演讲 PPT，推荐 3 个风格方向让我选」
「做个 AI 番茄钟 iOS 原型，4 个核心屏幕要真能点击」
「把这段逻辑做成 60 秒动画，导出 MP4 和 GIF」
「帮我对这个设计做一个 5 维度评审」
```

没有按钮、没有面板、没有 Figma 插件——这也是作者的出发点：Claude Design 发布那天他玩到凌晨四点，几天后发现自己再也没点开过它。「不是它不好，是我宁愿让 agent 在终端里干活，也不愿意打开任何图形界面。」

## 坑

### 1. 仓库 231MB

风格样张（92 种，每种一张 jpg + 一份 html 源码）、24 个预制样例、9 个能力演示的 GIF/MP4 都在仓库里。`git clone` 和 `npx skills add` 都会慢，别以为是网络问题。

### 2. 版本快，教程容易对不上

4 月开源，10 月已经 3.1，两个月里风格库从 84 种变成 92 种。仓库简介写的还是「84 种」，README 是「92 种」——看教程时先确认版本，别对着 2.0 的 GIF 找 3.1 的功能。

### 3. 作者自评：80 分

`Limitations` 那节写得很直白，三条都值得先知道：

- 不支持图层级可编辑的 PPTX → Figma，也不能拖进 Keynote 改文字位置
- Framer Motion 级别的复杂动画（3D、物理、粒子）超出边界
- **完全空白的品牌从零设计，质量会掉到 60–65 分**

最后一句尤其诚实：凭空画 hi-fi 本来就是 last resort。

### 4. 它周边依赖不少

动画剪辑靠同作者的 `huashu-motion`，演示贴纸来自 `huashu-bird-sticker`（那部分是 PolyForm Shield 1.0.0，不是 MIT，只用于演示版式，作品里要换成自己的素材）。想要配音走豆包 TTS 的话还得自己备 key。

### 5. 文档的营销浓度不低

全篇 GIF、案例、Live demo、「大厂设计团队」这类措辞不少。信息量确实大，但读的时候要把「这是什么」和「这有多好」分开看——好在它自己那节 Limitations 又把天平拉回来了一点。

## 适合谁

| 适合 | 不适合 |
|---|---|
| 要出 PPT、宣传图、发布动画但不想开设计软件 | 需要图层级可编辑、要交付 Figma 源文件 |
| 品牌资产齐全，或者愿意按它的 5 步协议去抓 | 全新品牌、什么素材都没有（会掉到 60 分） |
| 一个人干完设计 + 交付的独立开发者 | 团队有专职设计师、有既定规范 |
| 需要批量出小红书 / 信息图这类版式活 | 需要 3D、物理模拟、粒子系统 |

## 一点判断

三篇设计类工具读下来，最能区分它们的问题不是「哪个更懂审美」，而是**它们各自假设了什么是对的**：

- taste-skill 假设「从零开始的页面需要一个被发牌的方向」
- impeccable 假设「大部分问题可以写成规则，规则要挂到编辑循环上」
- huashu-design 假设「决策权在人，工具负责把选项摆到人眼前、把交付物做出来」

第三个假设最保守，也最经得起时间——因为它的核心资产（92 种样张、六个候选的流程、外观账本）不会因为「明年 AI 审美变了」而失效，只会越用越准。

真正值得抄的不是它那 92 种风格，是那三轮盲选的记录：**第一轮证明「强制隐喻」不行，第二轮证明「堆禁令」更不行，第三轮才找到「加选项」**。大多数工具文档只写最后成功的那一版，它把输掉的两轮也写出来了——这比任何规则清单都值钱。
