> 说「可爱一点」，每次出来的都不一样。说 `FB-006`，每次都朝同一个方向。

这个项目干的事很简单：把「画风」这种形容词，变成可以指着说的编号。

| 项目 | 内容 |
|---|---|
| 类型 | Agent Skill（提示词库 + 编号图鉴 + 交互画廊） |
| 仓库 | [yang0/handraw-style](https://github.com/yang0/handraw-style) |
| 许可 | MIT **+ 强制署名**（GitHub 识别为 NOASSERTION） |
| 体量 | 1038 个文件约 51MB；仓库含历史约 420MB |
| 热度 | 6.8k star / 780 fork / 6 open issue（2026-10-31 快照） |
| 状态 | 2026-09-05 开源，2026-10-28 仍在更新 |

## 它不生成图，它生成提示词

分清这一点很重要：它不会替你出图，它把「你想要什么画风」翻译成一段中英双语的生图提示词，你拿去 Midjourney、DALL·E、Stable Diffusion、Flux 或 gpt-image-2 里生成。

三个编号系统：

| 维度 | 数量 | 编号 |
|---|---|---|
| 视觉风格 | 365 种（手绘 + 写实） | `FA`–`FI` 九类 + 三位数字，如 `FB-006`，旧编号 `041` |
| 排版图型 | 170 种 | 社媒卡、信息图、漫画分镜、IP 设计、电商 |
| 经典单色 | 36 种 | `C-01`–`C-36`，六大色系（克莱因蓝、鼠尾草绿、爱马仕橙、佩恩灰…） |

![前 16 种风格预览：每一格标着一位插画师的名字与风格编号](/imgs/ai-toolbox/handraw-style/style-sheet.webp)

看图就能明白它的组织方式：每一格 = 一种可被引用的画风，左上角是编号和名字。剩下 349 格同理。

## 它真正解决的问题：描述会漂移

这是我认为它唯一有分量的地方，值得说透。

「可爱一点」「文艺一点」「有手账感」——这些词对模型来说没有稳定解。同一个提示词跑十次，出来十个方向；换个人描述，又是另一个方向。这在单人创作时只是麻烦，在协作和复现时是灾难。

编号解决的是**引用问题**。有了 `FB-006`：

- 你可以跟别人说「用 FB-006 那个风格」，对方能查到同一格；
- 你可以在三个月后回到同一个风格，不用凭记忆复述；
- 你可以把风格和排版、配色拆开组合（`图型 SC-001 + 风格 FB-006 + 主题色 C-01`）；
- 你可以讨论它——「FB-006 太规整了，换 FC-029 试试」。

这跟 Pantone 色号、设计 token 是同一类东西：**把隐性知识离散化，让它可引用。** 一个画师说不清自己的风格，但他能指着说「就要这种」；这个库把这句「指着」变成了字符串。

## 七种用法，本质是三件事

README 列了七种模式，去掉包装其实是三类：

**一、选风格出提示词。** 智能推荐（只给主题，它替你选风格和配色并给理由）/ 精准指定（`FB-006 号风格，主题：秋天的第一杯奶茶`）/ 海报模式（8 个字段的结构化提示词）。

**二、围绕一篇文章做一套图。** 封面模式（塞全文或字幕，它提炼 200 字摘要 + 受众画像 + 隐喻再出图）、长文配图模式（规划 2–5 个插图点位 → 全篇锁同一风格与色 → 批量出图 → 自动回填 Markdown）。

**三、摄影企划。** 情侣/婚纱/写真/全家福等 10+ 题材，先出 3 个差异很大的时空方案（2 个真实地标 + 1 个穿越/虚构），每个方案封成独立代码块，末尾直接带「出 8 宫格图片」，回复 A/B/C 就开跑。

还有一个双模式开关挺实用：**纯图模式**（画面自己说话）和**图文模式**（把你写的主题原文放进构图里，适合金句卡和海报）。

## 一个诚实的工程细节：模型适配

生图提示词最容易吹牛的地方是「我们的提示词在所有模型上都一样好用」。它这里写得比较实在：

- **已标定的模型**（首发深度适配 `gpt-image-2`）：建了全量风格的激活能力清单，优先级是「作者名 + 风格名 → 注入正向核心特征 → 实在不行才传参考图」。理由是避免无谓传图把主体构图锁死。
- **未标定的模型**（Midjourney、Flux、SD、Imagen、Gemini 等）：走「4 宫格参考垫图」兜底——不指望关键词能激活，直接给图让它照着画。
- 能力矩阵是开放的 JSON（`references/model_capabilities.json`），欢迎社区提交实测数据。

「同一段提示词在不同模型上不是同一个效果」，这句话它没藏着。

## 它和前两篇设计工具是同一个方向

这个集合里已经有三篇设计类工具了，放一起看会发现它们在干同一件事——**把审美离散化成可引用的单元**：

| | 单位 | 解决什么 |
|---|---|---|
| impeccable | 62 条确定性规则 | 判定：这样算不算 AI 味 |
| huashu-design | 92 种带样张的风格 | 起步：从零该往哪走 |
| handraw-style | 365 + 170 + 36 个编号 | 复用：同一种风格怎么再来一次 |

离散化的好处是可复现、可组合、可讨论。代价也很清楚：**用同一个库的人，产出会越来越像。** 571 个选项听着很多，但所有用户都在同一个池子里抽签，长期看会收敛成一种「这个库的味道」。huashu-design 用「外观账本」记你最近做过什么来对抗这件事，这里没有对应机制。

## 坑

### 1. 文档里的数字前后不一致

这不是小事，因为你可能照着数字去规划产出：

- 正文说「001–365 种风格」，图鉴标题写「367 种完整风格拼图大表」；
- 排版图型正文说 170 种，但分类明细加起来是 161（社媒卡 21 + 信息图 35 + 漫画分镜 68 + IP 13 + 电商 24）；而「特色」那张表又写 24 + 38 + 71 + 13 + 24 = 170。

**以图鉴（STYLES.md / LAYOUTS.md）里的实际条目为准**，别按汇总数字做预算。

### 2. 体积：为 51MB 的内容下 420MB

当前 1038 个文件、约 51MB（大头是 `images/individual` 18.7MB 和 `images/layouts` 18MB）。但仓库含历史是 **420MB 左右**——三百多张风格图改过好几版，全在 git 历史里。`git clone` 会比较难受，能用浅克隆就用浅克隆。

### 3. 许可不是标准 MIT

`LICENSE` 的标题写的是「MIT License (with Attribution Requirement)」：可以自由使用、修改、商用，但**要求保留作者 yang0 与原仓库地址**。GitHub 无法识别这套条款，所以标成 `NOASSERTION`。

商用没问题，但署名这条是硬要求，不是「欢迎」。

### 4. 风格大多直接挂在在世插画师名下

图鉴里每一格标着一位插画师的名字：Gemma Correll、Saul Steinberg、Edward Gorey、David Shrigley、Christoph Niemann、Jean Jullien……示例图看起来就是这些人的已发表作品。

两件事要自己想清楚：

- **风格模仿的边界**：用艺术家名字做风格提示词在 AI 生图里很普遍，但商业化使用时，模仿特定在世作者的作品风格是有争议的（部分平台甚至在政策里限制直接点名艺术家）。这个库不替你做判断。
- **预览图的版权**：如果那些示例确实是原作，它们的版权属于原作者，不在仓库的 MIT 声明覆盖范围内。拿去当素材用之前先想一层。

### 5. 它只管提示词，不管出图

编号是稳定的，模型不是。同一个 `FB-006` 在 gpt-image-2 和某个通用模型上出来的是两种东西，这也是它为什么要给未标定模型准备垫图兜底。**别把编号当成出图保证。**

### 6. 社群和引流占比不小

微信群二维码、个人微信、飞书知识库、变现经验分享——中文开源项目的常见形态，内容是真的，但读的时候要分清哪部分是技术文档、哪部分是运营。

## 适合谁

| 适合 | 不适合 |
|---|---|
| 做小红书 / 公众号 / 知识长图，要稳定的画风 | 需要原创视觉体系、要跟别人不像 |
| 一篇文章要一套风格统一的插图 | 一次性配图，不值得翻 571 个编号 |
| 想快速试不同画风，但说不清术语 | 只用一个模型、且该模型不吃关键词 |
| 团队协作，需要「用第几号」这种明确指代 | 在意风格署名伦理与版权风险 |

## 一点判断

它真正的资产不是 365 张图，是**那套编号**。编号让风格从形容词变成名词，从此可以被指着说、被检索、被组合、被讨论——这是把隐性知识显性化的经典操作，价值不在「多」，在「可引用」。

但离散化有另一面，而且是这一整类工具共同的问题：**571 个选项会让人停止描述自己真正想要的东西。** 你本来想要「雨天窗户上水汽的质感」，翻了十分钟图鉴，最后选了 `FB-006`，因为它看起来接近。选择变容易了，但你离最初那个念头远了。

所以我的用法建议是反过来的：**先自己想清楚要什么，再去编号里找最接近的一格**，而不是先打开图鉴，让库替你决定想画什么。

最后一句留给署名那件事：这个库对「保留作者」的要求写得很清楚，而它自己大量引用了别的插画师的名字和作品。这不矛盾——它是一个索引，不是原作——但用它产出商业内容时，那层版权与伦理的判断，库替不了你。
