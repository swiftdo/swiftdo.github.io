> 「不是 X，而是 Y。」
> 「说到底，真正重要的是……」
> 「让我深吸一口气。」

这些句子你一眼能认出来。这个技能做的事，就是把它们从文字里删掉——而且它删的依据不是「这些词像 AI」，是「这些句子没有在说事，在摆姿势」。

## 它从哪来

不是作者自己总结的审美，而是**维基百科编者用来抓 AI 稿的那份指南**——《Wikipedia: Signs of AI writing》，由 WikiProject AI Cleanup 维护。

这有个微妙之处：那份指南是**人用来识别 AI** 的，这个技能反过来用它**消除痕迹**。同一套知识，正向是检测，反向是规避。

作者对此的态度写在 README 里，而且写得很干脆：

> Humanizer 是为人类读者改稿。**绕过 AI 检测器不是目标，而且检测器仍然会标记它的大部分输出。**

这句话让整个项目站得住。它没有许诺「让你的文字通过检测」，它许诺的是「让文字读起来不像是摆姿势」。

## 五条最狠的

README 挑了五条最强的，都是「看一眼就该改」的：

| 模式 | 长什么样 |
|---|---|
| **不是 X，而是 Y** | 「这不只是一个功能，而是一次协作方式的转变。」 |
| **一句话收尾** | 每节后面跟一句「这才是真正的价值。」 |
| **听起来很深的格言** | 「本质上，真正重要的是……」 |
| **先搭台再说话** | 「说实话？」「让我们深入看看。」 |
| **跟没人在争论** | 「我不是说 X，但是……」 |

第 5 条最妙。「跟没人在争论」指的是：作者先虚构一个反对意见，再把它驳倒——而那个反对意见从来没人提过。读的时候觉得很严密，其实是在跟空气搏斗。

## 26 个模式，分六类

完整清单在 README 里，六组：

- **A. 编排代替陈述**（1–5）：就是上面那五条
- **B. 按规则制造节奏**（6–11）：强行三段式、句首重复、破折号当万能连接符、叠加限定词、到处加连字符
- **C. 膨胀与借来的权威**（12–17）：`delve`/`landscape`/`testament` 这类词、给事实加戏（「标志着关键时刻」）、模糊关联、-ing 结尾的浅层补充、销售语言、「专家认为」
- **D. 按规则排版**（19–21）：把加粗当装饰、装饰性标题（「🚀 启动阶段：」）、弯引号
- **E. 聊天和草稿的残留**（22–25）：`Great question!`、`I hope this helps!`、「在现有资料有限的情况下……」、标题在第一句里重说一遍
- **F. 写给错的读者**（26）：把对方已经知道的事重新解释一遍

读完这 26 条，你会发现一件事：**大部分不是「用词问题」，是结构问题。** 第 1、3、4、5 条全是「先摆一个姿态，再说内容」；第 13、16、17 条全是「给事实加戏」。真正属于「某个词被用烂了」的，只有第 12 条和第 21 条（弯引号）。

这也解释了为什么简单的「同义词替换」没用——把 `delve` 换成 `explore`，那个姿态还在。

## 它对「人味」的定义很准

README 里这段我认为是全篇最好的一段：

> 语言模型写的是「最可能接下去的内容」，所以它默认会选**最适合最多读者和最多主题**的那个说法。而人是**为一个读者、一个主题**做选择。

**每一个 AI 味，都是这种默认选择的产物**：一句宣告重要性却不增加事实的话、按规则套上的节奏或排版、把普通事实装扮成关键转折、从聊天里漏出来的残留、以及把读者已经知道的事再讲一遍。

所以「人味」不是更口语、更多口头禅、更多「说实话」。是**有一个具体的读者在**。

## 它怎么改：三步，而且会给你看

粘一段文字进去，它给三样东西：

1. 第一版改写；
2. 一段对自己的批评——还有哪里像机器写的；
3. 最终版。

指向文件时，它**只改散文**，代码、数据、frontmatter、链接目标都不碰。个人写作保留作者的观点和怪癖（比如你就是爱用破折号），技术文档保持中性平实。

还支持**声音匹配**：先给它两三段你自己写的东西，它会跟着你的节奏、用词、标点和你故意的怪癖走——包括你确实爱用破折号这件事（第 8 条「破折号当万能连接符」在原文里标着 *weak alone*，单独出现不算数）。

## 效果：一个诚实的数字和一个要打折的数字

**诚实的**：作者明说它过不了 AI 检测器，而且检测器会标记它的大部分输出。

**要打折的**：README 说在一次盲测里，评委 16 次全票选了它的改写版本（引用自家 issue #229）。16/16 很漂亮，但那是**自测**，没有第三方复现。看看 README 开头那段前后对比，你自己判断更靠谱。

## 坑

### 1. 它不保证过检测器

作者自己说的，而且很明确。如果目的就是「不被识别成 AI」，这个工具帮不上——它优化的是阅读体验，不是分类器。

### 2. 会改掉你故意的风格

它默认会砍破折号、砍一句话收尾、砍三段式。如果你本来就想这么写，得靠「声音匹配」给它样本，或者明确告诉它保留。

### 3. 有些模式单独出现不算

第 8、9、10、11、21 条标着 *weak alone*——只有一段里同时出现多个才算。这个设计很克制，但也意味着**它不会给你一个干净的「命中清单」**。

### 4. 事实不能凭空补

README 明确写了：名字、数字、日期、引用必须来自原文或作者，缺细节它会问，不会编。所以它的改写有时会「变空」——因为原文本来就没什么内容。

### 5. 中文效果没保证

26 个模式全部基于英文语料（维基百科的英→中差异很大）。中文的「AI 味」有另一套特征——比如「首先/其次/最后」的三段式、「值得注意的是」、「赋能」——这个技能没覆盖。中文稿子用它，指望它删掉「不只是 X，而是 Y」还行，指望它整体去味会失望。

## 适合谁

| 适合 | 不适合 |
|---|---|
| 改营销文案、发布公告、公众号初稿 | 想绕过 AI 检测 |
| 英文写作，尤其非母语者 | 纯中文稿件（覆盖面有限） |
| 想让 AI 代笔的稿子读起来像自己写的 | 需要保留原有修辞风格的文学写作 |
| 团队统一对外文案的语气 | 一次性改一两个句子 |

## 一点判断

这个集合里已经有一堆「去 AI 味」的设计工具，但那些都在管**视觉**：渐变、卡片、小标签。humanizer 管的是**句子**，而它的结论比设计那边更普适：

**AI 味的本质不是某种风格，是没有具体的对象。** 模型对所有人说话，所以它说的是所有人的平均值；人只对一个人说话，所以说得出具体的句子。

这也解释了为什么设计那边的禁令会互相打架（impeccable 禁奶油色，huashu-design 说不禁），而这边不太会——「不要说『让我深吸一口气』」在任何语境下都成立，因为它不是在反对一种风格，是在反对一种**没话找话**。

要泼的冷水很直接：它是英文的。中文的 AI 味有另一套肌肉记忆，26 条模式覆盖不到。但那份方法论——**找出「摆姿势」而不是「说事」的句子**——可以直接搬过来自己列。
