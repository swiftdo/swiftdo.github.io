# OpenAI 推出 Images 2.6：直出 GIF 和 SVG，出图快 50%

OpenAI 在 2026 年 11 月 4 日发布了新一代图像模型 **Images 2.6**，同步上线 ChatGPT、Codex 和 API 三个入口。官方的说法是：出图速度比上一代快 50%，ChatGPT 里可以用一句话生成 GIF 动图，API 侧则补上了 SVG 矢量导出、圈画式局部编辑（markup）和一个控制"规划力度"的 `complexity` 参数。

价格没有涨，和 GPT-Image-2.5 同档。

这次更新真正值得写的地方，不是画质又涨了几个点——官方甚至没把画质当作主要卖点——而是**图像模型开始直接产出"可交付格式"**。以前要拼三四个工具才能完成的动图、矢量、精确局部修改，现在一个接口就能出。

## 这次更新了什么

### ChatGPT / Codex 端

- **GIF 动图**：输入一句提示词，或上传一张已有图片，直接生成循环动画。生成后可以调整播放速度、逐帧查看，并对单独某一帧再修改。
- **参考图库**：可以把自己、宠物、角色存成参考图，之后新建图片时直接调用，不必每次重新上传。
- **速度**：整体出图时间缩短约 50%。
- **覆盖范围**：全球所有订阅档位，桌面端、移动端、网页端，Codex 里同样可用。

### API 端

| 能力 | 说明 |
|---|---|
| `gpt-image-2.6-flare` | 主打速度与版式。`quality: "low"` 下最快约 6 秒出图，海报、电商产品图这类讲究排版的场景有改进 |
| `gpt-image-2.6-sunburst` | 主打细节与一致性。中/高质量下画质更高，多轮编辑之间更能守住角色、产品和品牌细节 |
| `complexity` | 新增参数，`low` / `medium` / `high`，控制模型动笔前花多少算力做场景规划，默认 `high` |
| `markup` | 图像标记编辑，此前只在 ChatGPT 网页端有，现在开放给 API |
| `output_format: "svg"` | 直接导出矢量图 |
| `output_format: "gif"` | 直接输出动图 |

两个模型都只支持 `POST /v1/images/generations` 和 `POST /v1/images/edits` 这两个端点。按文档提示，使用 GPT Image 系列前可能需要在控制台完成组织验证。

## complexity：把"想多少"和"画多细"拆开

这是整次更新里最有工程价值的一处设计。

过去调生图 API，开发者能拧的旋钮基本只有分辨率和笼统的 quality 档位。哪怕只是把背景从灰改成白，模型也要重新完整跑一遍构图规划——钱和时间都花在了"重排兵布阵"上。

Images 2.6 把这件事拆成了两个参数：

- `quality` 管**渲染精细度**，也就是像素层面的细节和保真度；
- `complexity` 管**动手前的规划量**，也就是模型愿意花多少算力去理解多元素关系、约束条件和文字排版。

思路和文本模型里调推理深度是同一套：简单任务少想一点，复杂构图多想一点，把延迟与效果的取舍交回给开发者。官方给的用法建议也很直白——大多数编辑任务用 `low`，换背景、改招牌这类局部修改没必要重新规划全局；只有元素多、约束多、文字密集的场景才上调到 `medium` 或 `high`。

调节 `complexity` 不额外收费，但延迟会随之上升，而且官方也提醒：复杂度调高可能引入你并不想要的改动。所以这不是"能调高就调高"的参数，最好拿自己的真实素材做一次对比。

```python
from openai import OpenAI

client = OpenAI()

result = client.images.generate(
    model="gpt-image-2.6-sunburst",
    prompt="把招牌底色改成深墨绿，其余保持不变",
    quality="high",       # 渲染精度拉满
    complexity="low",     # 但别重新规划整个画面
)
```

上面这段是典型的"局部改图"配置：高画质 + 低复杂度。省掉的是规划时间，留下的是重绘精度。

## GIF 是怎么做出来的：一张序列帧，不是视频模型

原生 GIF 是这次最出圈的功能，但它的实现路径可能和直觉相反——**Images 2.6 没有去动视频那套时空扩散计算**。

从 OpenAI 公布的 OpenArt 合作案例提示词能看出门道：模型被要求生成一张"用于无缝循环 GIF 的动画序列图（sprite sheet）"，严格包含 6 个连续帧，按 3 列 × 2 行排列，从左到右、从上到下阅读，每格尺寸完全一致，机位固定，角色、服装、桌面和背景保持一致，第六帧要平滑过渡回第一帧。

这是游戏工业里做定格动画的老办法。好处很实际：

- **绕开了视频模型的推理延迟**，生成一条几秒的动图不需要几十秒的等待；
- **天然保证帧间一致**，因为所有帧是在同一张图里一次性画完的，五官、衣褶、背景物体的相对位置不会在帧与帧之间漂移；
- **不需要额外工具链**，切片、合成、循环，都在服务端完成。

API 侧的参数对应如下：

| 参数 | 取值范围 | 默认值 |
|---|---|---|
| `frame_count` | 2 – 64 帧 | 9 |
| `frame_duration_ms` | 20 – 2000 毫秒（按 10 毫秒取整） | 200 |

9 帧 × 200 毫秒，正好 1.8 秒一个循环。限制也要注意：GIF 只能在 generations 端点输出，不支持流式返回和局部预览，`edits` 端点不能产出 GIF；帧数、单帧尺寸和生成数量要一起落在模型的像素上限内，超了就减帧、减尺寸或者减 `n`。

已经在用的例子包括 OpenArt（GIF 创作）和做 AI 办公助手的初创公司 Town——后者通过 API 给工作软件里的虚拟助手生成打字、反馈这类实时微表情动图。

## SVG 与 markup：从"生成图片"到"交付格式"

这两项不如 GIF 抢眼，但对开发者更实用。

**SVG 导出**解决的是一个长期存在的返工环节。AI 生成的位图放大就糊，想放进网页或 App，常规操作是再找个工具转矢量，转完还得手动清理路径。现在设 `output_format: "svg"` 就行，`n` 必须为 1。需要知道的是：接口会先生成一张参考位图再矢量化，`quality` 控制的是那张位图；产物是静态矢量，不含脚本、外部资源和内嵌位图，适合图标、Logo、插画。放进生产流程前，建议还是用 SVGO 之类的工具过一遍，检查路径数量。

**markup 圈画编辑**补上的是"mask 靠猜"的痛点。文档自己承认，mask 本质上是提示词驱动的，模型不一定严格按形状改。现在可以传一张透明背景的标注层 PNG——在原图上画圈、画草图——再配一句文字说明要改哪里。几个硬性约束：

- 只在 `POST /v1/images/edits` 上可用；
- 标注层必须与第一张输入图同宽同高，且保留透明像素，不能直接画在原图上合并；
- 原图与标注层各自不超过 16,777,216 像素，标注文件不超过 50 MB；
- 不能与 `mask`、`prompt_rewriter` 同时使用。

对做"AI 修图"类产品的团队来说，这直接对应一个前端交互：让用户随手圈一下，后端把那层透明 PNG 传上去。

## 数字背后的规模

OpenAI 同时更新了用量数据：ChatGPT、Codex 和 API 上**每周生成超过 40 亿张图片**，日均超过 5 亿张。作为对照，今年 9 月公布的数字是每周 30 亿张——两个月增加 10 亿张，增幅约 33%。

这个量级意味着两件事。一是图像生成已经不是"尝鲜功能"，而是 ChatGPT 的日常基础设施，速度优化带来的体验收益会被放大到每一次请求上；二是推理成本的压力是真实的，Flare 那种"6 秒出图"的定位，本质上是在给高频、低价值密度的请求找一条便宜路径。

早期测试伙伴包括 Picsart、fal、Sable、Higgsfield，以及 Figma Weave。Figma Weave 创意总监 Itay Schiff 的评价是，2.6 把速度和创作控制放在了一起；Picsart 的 GTM 总监 Davit Avoyan 则提到角色一致性更好、结果更准。OpenArt CEO Coco Mao 的说法更直接：「GIF 是社交媒体的母语，GPT-Image-2.6 让每个创作者用一句提示词就能说这门语言。」

## 冷静看：哪些是官方说法，哪些还没被验证

需要说清楚的是，50% 提速、编辑一致性提升这些结论，来源目前都是 OpenAI 官方和早期合作客户，**还没有第三方的系统评测**。有两件事建议自己测：

1. **GIF 的帧间连贯性**。序列帧方案在角色五官和背景上确实占优，但在快速动作、镜头推进这类场景里，六格定格能不能撑住，取决于题材。表情包和吉祥物小动作问题不大，复杂的运动场景别指望它替代视频模型。
2. **SVG 的路径质量**。位图矢量化出来的曲线，节点密度和曲线拟合质量因图而异。图标类通常干净，插画类可能出现大量碎路径。

另外一个附带消息：有开发者在谷歌云上发现了 `gpt-6.2-astra` 和 `gpt-6.2-sol` 的模型标识。这属于泄漏层面的传闻，OpenAI 没有确认，知道就好，别当结论。

## 实操建议

如果你的项目已经在用 gpt-image-2.5，升级路径很短：

1. **先换模型名跑回归**。价格不变，把 `model` 换成 `gpt-image-2.6-flare` 或 `gpt-image-2.6-sunburst`，对比延迟和效果，再决定是否全量切。
2. **编辑任务先试低复杂度**。默认是 `high`，小修小改显式设成 `low` 往往更快，也更不容易改过头。
3. **动图注意像素预算**。先用 `size: "auto"` 让接口自己选尺寸，再按需固定。
4. **面向终端用户带上 `safety_identifier`**。文档建议对用户名或邮箱做哈希后传入（不超过 128 字符），旧的 `user` 参数已标记弃用。

从 2.5 到 2.6 只隔了不到两个月。图像模型的迭代节奏已经和文本模型并行了，而这次的信号很清楚：竞争点正在从"画得多好看"转向"能不能直接交付"。
